# Project overview

Use this section for Potion Panic decisions that remain true across tasks.
These pages define the game, its delivery boundaries, and the runtime contract.
They do not replace task tickets, active plans, or reusable Unity guidance.

## Choose the right document

| If you need to know... | Open |
| --- | --- |
| What the player should experience and why | [Game design](game-design.md) |
| What is locked for the MVP, what is deferred, and delivery order | [MVP scope](mvp-scope.md) |
| Which Potion Panic systems, data, and dependencies own behavior | [Runtime contract](technical-architecture.md) |
| How to apply general Unity architecture principles | [Unity architecture primer](../guides/unity/runtime-architecture.md) |

## Reading order

1. Read [Game design](game-design.md) for the player-facing target.
2. Read [MVP scope](mvp-scope.md) before proposing or starting feature work.
3. Read the [Runtime contract](technical-architecture.md) before adding or
   reshaping a runtime system.

## Changing project truth

Use a ticket and, when needed, an implementation plan to propose a decision.
Update the owning project page only when the decision is accepted and stable.
Keep temporary implementation notes in tickets and plans rather than creating
parallel specifications.
