## Description

Implement a reusable `IngredientStation` that provides one configured
`IngredientData` through the common interaction path and respects the
single-item inventory rule.

## Acceptance Criteria

- [ ] `IngredientStation` participates through the common `IInteractable` path.
- [ ] Each station exposes one configured `IngredientData`.
- [ ] Successful interaction places the configured ingredient in `PlayerInventory`.
- [ ] Pickup is rejected while the player is already carrying an item.
- [ ] The station does not own or duplicate player inventory state.
- [ ] The same component can support later ingredient types through configuration rather than ingredient-name branching.
- [ ] Required prompt/interaction state remains compatible with the Milestone 2 interaction framework.
